# 交付判据

先定判据，再看数据。否则每个人都会拿着自己的「能跑」来争论。

## 一、功能：四列，逐样本 × 逐构建

| 列 | 含义 | 记录方式 |
|---|---|---|
| 编译通过 | shader 编译没报错 | 是 / 否 + 第一条错误原文 |
| 出画面 | 有非黑非灰的输出 | 是 / 否 |
| 渲染正确 | 和作者提供的参考图/截图对比，无缺层、无花屏、无闪帧 | 是 / 否 + 差异描述 |
| 报错类型 | validation error / 驱动崩溃 / 静默回退 | 原文 |

四列必须同时记。只有「出画面」是最容易骗人的：静默降级也能出画面。

**通过率差值**：同一份样本集，B+ 构建通过率减 A 构建通过率。这个差值才是「XFB + GS 解锁了什么」的证据，绝对值没有意义；B（只有 GS）跟 A 的差值预期是 0，正好当对照。

## 二、性能：第二轨，不参与通过/不通过

在功能四列之后单独记，且必须同机、同场景、同存档：

- 平均帧（3 次，丢掉第一次，避开 shader 缓存）
- 1% low
- 帧时间尖峰（>50ms 的次数）
- shader 预热时长（首次进入场景到帧稳定）
- 可选：功耗、显存

基线只有一个：**同一台机器上的苹果 GL 4.1**。没有这个基线，任何「比 XX 快」的结论都不成立。

但这个基线只在**苹果 GL 4.1 也跑得动**的样本上存在。GL 4.3+ 专属的样本（走新路径的 SSPT、compute/SSBO 负载）在基线上根本编不过，没有可比数，只记绝对值——它们不参与第六节第 4 条。

已知会污染结论的三件事，单独记录、不要混进均值：

- GS 用 compute 跑两遍，帧时间形态和原生 GS 不同；
- fans/quads 这类固定拓扑会被 CPU 展开，Playport 0093 记过 15.28ms → 1.59ms；
- 磁盘缓存首次/二次启动行为不同。

## 三、口径铁律

1. 任何数字必须带构建标识（A/B/B+/C）、commit、芯片、macOS 版本、抓取日期。
2. `MESA_GL_VERSION_OVERRIDE` 出来的版本号不算能力证据。
3. 不同构建的结果不能互相代言；C 的 4.6 不能说成 A 的。
4. `MESA_KK_EXPERIMENTAL` 不能为了凑特性而开；开了的结果单独标注，不进主表。
5. CTS 通过率不等于应用能跑（Hadron 原话：A pass here does not mean a game works）。

## 四、最小样本集

不是越多越好，是覆盖决策点：

| 样本 | 为什么必须在 |
|---|---|
| SSPT / 体素类 pack ×2 | 社区里最常被说「Mac 上不行」的那类 |
| 真 GS stage 负载 ×1 | 唯一能证明 GS 真的通了的样本 |
| 只有 fans/quads 的负载 ×1 | 会被 CPU 降级，混进均值会污染结论 |
| Voxy / DH 类模组 ×1 | 大量间接绘制，考的是另一组特性 |
| 非游戏 GL 应用 ×1 | 排除「只对 MC 调过」的质疑 |

## 五、这一轮（B+）算不算测成

这一轮只到 3.3，判据不许越过 3.3。三条同时满足：

1. 至少一台机器上，`zink_check_requirements` 的 `gl33` Supported；或 `gl30` Supported 而 `gl33` UNSUPPORTED（说明 XFB 已进、3.3 还差项，差集另行比对）——附逐档原文；
2. `vulkaninfo --json` 里 `VK_EXT_transform_feedback` 在，和第 1 条互相印证；
3. 同机有一张读到驱动名的截图或日志，排除静默回落到苹果 GL。

三条都不过也算数据：把原文贴回来，记「这一轮没测成」并写清卡在哪。**这一轮的结果不许拿去谈 4.2–4.6**，那是 C 的事。

## 六、什么算「这条路成立」（终局判据）

触发条件是 C 能自己编出来：Hadron 0038–0083 公开可复现（现在在对方仓库里，未上游）。没到这一步，这一节只是备忘，不拿来卡这一轮。

四条同时满足：

1. 三种芯片档（M1/M2、M3/M4、M5/M6）各至少一份完整记录；
2. 最小样本集里，GL ≥ 4.3 的路径能出正确画面（只有 C 越过 4.2，A/B/B+ 都到不了）；
3. 没有静默错误（渲染错但不报错的那种）；
4. 性能：只在苹果 GL 4.1 也跑得动的样本上比，GPU-bound ≥ 同机基线的 70%；4.3+ 专属样本没有基线，只记绝对值，不参与这一条。

第 4 条是门槛不是目标，但它只覆盖两种构建都跑得动的那部分样本。低于 70%，这条链只能当参考实现，不能当功能发。

## 七、什么算「该停」

提前写死，避免沉没成本：

- 目标负载**全是** GS 硬依赖，而 XFB 长期没有上游路径；
- 或 B+（叠了 !44928）在三类芯片上都到了 3.3，但 C 依赖的 Hadron 补丁长期不上游、也不维护——3.3 仍低于系统 GL 4.1，没有可交付的东西；
- 或 B+ 在三类芯片上都报不回 3.2 以上；
- 或连续两个 Mesa 发布周期，!44928 都没有推进。

命中任一条，关掉实施分支，保留调查结论。这不是失败，是把资源挪到有回报的地方。
